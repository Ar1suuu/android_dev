# Лайки и комментарии в базе данных

## Что сделано

Лайки постов, комментарии и лайки комментариев теперь хранятся в PostgreSQL. В качестве PostgreSQL используется Supabase, потому что он даёт готовый Postgres, REST API и в дальнейшем готовую регистрацию.

Flutter не подключается к PostgreSQL напрямую. Приложение работает через `supabase_flutter`, который обращается к REST API Supabase, а Supabase уже выполняет SQL-запросы в Postgres.

```text
Flutter
  └── supabase_flutter
        └── REST API Supabase
              └── PostgreSQL
```

## Почему Supabase

- это настоящий PostgreSQL, а не NoSQL;
- таблицы, внешние ключи и ограничения пишутся обычным SQL;
- не нужен собственный backend;
- позже можно добавить регистрацию, вход и выход без смены базы;
- лайки и комментарии можно будет привязать к `auth.uid()`.

## Схема базы данных

```text
users 1 ──── N posts
users 1 ──── N comments
posts 1 ──── N comments

users N ──── N posts      через post_likes
users N ──── N comments   через comment_likes
```

### users

Профиль пользователя.

| Поле | Тип | Смысл |
|---|---|---|
| id | bigserial | первичный ключ |
| username | text unique | имя пользователя |
| avatar_url | text | путь к аватарке |
| bio | text | описание профиля |
| created_at | timestamptz | дата создания |

### posts

Пост.

| Поле | Тип | Смысл |
|---|---|---|
| id | bigserial | первичный ключ |
| user_id | bigint | автор поста |
| image_url | text | путь к картинке |
| caption | text | подпись |
| created_at | timestamptz | дата создания |

### comments

Комментарий к посту.

| Поле | Тип | Смысл |
|---|---|---|
| id | bigserial | первичный ключ |
| post_id | bigint | пост |
| user_id | bigint | автор комментария |
| body | text | текст комментария |
| created_at | timestamptz | дата создания |

На `body` стоит ограничение `check (length(trim(body)) > 0)`. Пустой комментарий база не примет.

### post_likes

Кто лайкнул какой пост.

| Поле | Тип | Смысл |
|---|---|---|
| post_id | bigint | пост |
| user_id | bigint | пользователь |
| created_at | timestamptz | дата лайка |

Первичный ключ составной: `(post_id, user_id)`. Поэтому один пользователь физически не может поставить два лайка одному посту.

### comment_likes

Кто лайкнул какой комментарий. Устроена так же, как `post_likes`, только по `comment_id`.

## Как считаются лайки

Отдельного поля `like_count` в таблицах нет. Количество лайков считается по строкам:

```text
likeCount = количество строк в post_likes для этого поста
```

Это честнее, чем хранить счётчик, потому что счётчик может разойтись с реальными лайками. Для 10 постов и 15 пользователей такой подсчёт работает мгновенно.

Лайк текущего пользователя определяется так:

```text
isLiked = есть ли строка post_likes с этим post_id и user_id
```

Для комментариев используется точно такая же логика через `comment_likes`.

## Как работает лайк поста

1. Пользователь нажимает на сердце.
2. `PostWidget` вызывает `postsProvider.notifier.toggleLike(postId)`.
3. Нотифаер вызывает `PostServices.togglePostLike`.
4. Если лайк уже был, из `post_likes` удаляется строка.
5. Если лайка не было, в `post_likes` вставляется строка.
6. После успешного запроса обновляется состояние Riverpod.
7. Интерфейс перерисовывается.

Повторный лайк не создаёт дубль, потому что в таблице стоит составной первичный ключ.

## Как работает комментарий

1. Пользователь открывает шторку комментариев.
2. Вводит текст и нажимает отправку.
3. `CommentsSheet` вызывает `postsProvider.notifier.addComment`.
4. `PostServices` делает `insert` в таблицу `comments`.
5. База возвращает `id` нового комментария.
6. Новый комментарий добавляется в состояние Riverpod.
7. Список комментариев и счётчик обновляются на экране.

Комментарии загружаются из базы вместе с постами. Для каждого комментария отдельно подтягиваются лайки из `comment_likes`.

## Как работает лайк комментария

1. Пользователь нажимает на сердце рядом с комментарием.
2. `CommentWidget` вызывает `postsProvider.notifier.toggleCommentLike`.
3. `PostServices` вставляет или удаляет строку в `comment_likes`.
4. Состояние Riverpod обновляется.
5. Сердце и счётчик перерисовываются.

## Загрузка данных

`postsProvider` теперь является `AsyncNotifier`. У экрана есть три состояния:

- загрузка — показывается индикатор;
- ошибка — показывается текст и кнопка повтора;
- данные — показывается лента.

При загрузке выполняются запросы к пяти таблицам:

- `users`;
- `posts`;
- `comments`;
- `post_likes`;
- `comment_likes`.

Запросы идут параллельно. Потом данные собираются в модели `PostModel` и `CommentModel`.

## Текущий пользователь

Пока регистрации нет, приложение считает текущим пользователем `aminloh`. Его id берётся из таблицы `users` по username.

Когда будет добавлена регистрация, этот шаг заменится на `auth.currentUser`, а `users.id` будет связан с `auth.users.id`.

## Как запустить

1. Открыть Supabase Dashboard.
2. Перейти в SQL Editor.
3. Вставить содержимое файла `supabase/schema.sql`.
4. Нажать Run.
5. Запустить приложение:

```bash
flutter run -d macos
```

Скрипт создаёт таблицы и заполняет их тестовыми данными. Он также перезагружает схему PostgREST, чтобы новые таблицы сразу стали доступны через API.

## Как проверить

1. Поставить лайк посту.
2. Закрыть приложение.
3. Открыть приложение снова.
4. Лайк должен остаться.
5. Открыть комментарии.
6. Написать комментарий.
7. Закрыть и открыть приложение.
8. Комментарий должен остаться.
9. Поставить лайк комментарию.
10. Перезапустить приложение.
11. Лайк комментария должен остаться.

Дополнительно можно открыть таблицы в Supabase и увидеть новые строки в `post_likes`, `comments` и `comment_likes`.

## Короткий ответ для защиты

Лайки, комментарии и лайки комментариев хранятся в PostgreSQL. Flutter обращается к базе через Supabase REST API. Для лайков используются таблицы `post_likes` и `comment_likes` с составным первичным ключом, поэтому дубли невозможны. Количество лайков считается по строкам, а признак лайка текущего пользователя вычисляется отдельно. Комментарии хранятся в таблице `comments` и связаны с постом и пользователем через внешние ключи. На этом шаге регистрация ещё не добавлена, поэтому текущим пользователем считается `aminloh`, а RLS временно выключен.
